# 界面多语言

面板界面支持中文 / English。本文是这套机制的契约与改造进度，换窗口接手照此执行。

## 设计

**站点级选档，访客级解析。**

管理员在「站点设置 → 站点信息 → 界面语言」选一档，存服务端 `settings` 表（key `lang`）：

| 档位 | 行为 |
|---|---|
| `auto`（默认） | 每位访客各自按浏览器语言解析：首选语言以 `zh` 开头 → 中文，其余 → 英文 |
| `zh` / `en` | 全站强制，所有访客一致 |

默认给 `auto` 而不是 `zh`：老站点升级上来，中文浏览器解析结果仍是中文，行为不变。

**部署期可以先定一档**：环境变量 `MOSS_LANG`（`auto` / `zh` / `en`），由 `ensureLang()`（`server/api.go`）在首次启动时落进 settings。一键脚本 `deploy/moss.sh` 首次安装时会问一句，把选择转成这个变量。

三条约束，与 `MOSS_ADMIN_PASSWORD` 完全对称：

- **只在 settings 里还没有 `lang` 这一行时生效。** 之后改 `MOSS_LANG` 一律忽略——语言是管理员在后台改的东西，不该被一个部署期的环境变量在每次重启时覆盖回去。
- **没设也要写一行 `auto`。** 那一行就是「已经定过」的标记；不写的话每次启动都会重走这段，老库升级上来时会被后加进 compose 的 `MOSS_LANG` 悄悄改掉。
- **认不出的值要打日志**（`parseEnvLang` 比 `normLang` 宽容，认 `EN` / `zh-CN` / 前后空格）。静默回落 `auto` 会让人以为已经生效。

脚本只在**首次**（数据卷为空）才问：复用旧卷时 `MOSS_LANG` 不生效，问了也白问，那种「问了却没用」比不问更糟。

首页对外公开，所以语言档位随公开接口 `GET /api/site` 下发 —— 访客不登录也要拿得到，否则 `auto` 之外的两档形同虚设。

**不引 i18n 框架。** 这套面板要的只是「查表 + 插值」，react-i18next 的命名空间、懒加载、复数规则一样不用。状态用 `useSyncExternalStore` + 模块级订阅表，与 `web/src/api/store.ts` 同构；档位持久化与跨标签同步照搬 `web/src/useTheme.ts`。

## 契约

### 文案表

- `web/src/i18n/zh.ts` 是**基准表**，`TextKey` 由它推导。
- `web/src/i18n/en.ts` 用 `Dict = Record<TextKey, string>` 约束，**少一条 key 就过不了 `tsc --noEmit`**（已挂在 `npm run build` 里）。漏翻在构建时炸掉，不会上线后在英文界面冒出中文。
- key 命名 `模块.含义`，层级用点号：`settings.password.hint`、`dash.empty`。
- 插值占位写 `{name}`，调用 `t('key', { name: 3 })`。缺参数时原样保留占位符，界面上看得见。
- 语言名（`中文` / `English`）两张表里都用原生写法，不跟着界面语言翻译 —— 选语言的人未必看得懂当前这门语言。

### 四条硬约定

1. **不做单复数，用措辞规避。** 英文 `1 region` / `3 regions` 不开分支：要么把数字从名词旁挪开（`Regions` 当列头、值只留数字），要么换成单复数同形的说法（`{n} vCPU`、`{n} of your nodes`）。两张表本就可以结构不同 —— 中文写「{n} 个地区」，英文写「{n}」，这是文案表该干的事，不是缺陷。写 `node(s)` 一律算没做完。
2. **富文本拆前后缀，不引 Trans 组件。** 文案中间夹 `<b>` 或图标时，拆成 `xxx.before` / `xxx.after` 两条 key，JSX 里拼。见 `gcp.del.*`、`task.dragHint.*`、`srv.dragHint.*`。
3. **`t` 是保留名。** 项目里大量 `map((t) => …)`、`(t: number) =>`、`let t = '…'` 会遮蔽翻译函数。接入时一律重命名局部变量（`task` / `ts` / `item` / `title`），不要给 `t` 起别名 —— 全站统一叫 `t` 才好读。
4. **列举用 `list.sep`。** 中文顿号、英文逗号加空格，别硬编码 `'、'`。

### 模块级常量怎么办

`ranges` / `tabs` / `CAPS` / `UPGRADE_STAGE_KEY` 这类表在模块加载时求值，那时拿不到 `t`。一律存 `TextKey`，渲染时再查：

```ts
const tabs: Array<{ key: TabKey; labelKey: TextKey; icon: ... }> = [
  { key: 'servers', labelKey: 'admin.tab.servers', icon: Server },
]
// 渲染处：{t(item.labelKey)}
```

模块级**纯函数**（`upgradeTitle`、`capLabel`）用 `translate(getLang(), key)`：它们的结果只进 `title` 属性，不需要订阅重渲染。`useEffect` 里的 toast 同理 —— 用 `translate` 而不是闭包里的 `t`，免得把语言拖进依赖数组、切一次语言就重置一次定时器。

### 用法

```tsx
const { t } = useT()          // 组件内；语言切换时自动重渲染
t('settings.save')
t('dash.selected', { n: 3 })

translate(getLang(), 'key')   // 渲染期的纯函数里用（如 utils/format.ts）
```

### 后端

- `normLang()`（`server/api.go`）收敛取值，**读写两端都过**：写入端挡构造的请求体，读取端兜手工改库的脏值。任一端漏网，前端会拿着查不到表的语言码把整页渲染成一串 key。
- 字段挂在 `settingsView`（`server/admin_api.go`）与 `handleSite`（`server/api.go`）。

### 顺带修掉的两个真问题

- **`Dashboard` 分组筛选**：「全部」原本既是筛选状态值又是显示文本，一旦翻译，切换语言后 state 停在旧语言那个字符串，与新按钮对不上，列表当场筛成空。改用 `null` 哨兵，显示时才查表；顺带也不必再剔除用户自建的同名分组。
- **`SettingsTab` 保存后的 toast**：用的是闭包里保存前的 `t`，刚把界面切成英文却弹一句中文。改成按落档后的语言取文案。

## 怎么验

```bash
cd web && npm run verify     # tsc → vite build → 浏览器冒烟
# 等价的分段输出版本：bash web/tools/verify.sh
```

**别单跑 `npm run test:i18n`** —— 它不重新构建，会拿旧的 `dist/` 跑，改了源码照样全绿。一律走 `npm run verify`。

冒烟测试 `web/tools/i18n-smoke.mjs` 用 playwright-core 驱动系统 Chrome/Edge，接口全部 route 拦截（假数据在 `tools/fixtures.mjs`），不依赖后端。25 项断言分三类：

1. **档位真值表** —— auto 跟随访客、zh/en 压过访客、脏档位回落，共 6 条；外加跨标签 storage 同步 1 条。
2. **英文界面不得残留汉字** —— 13 个扫描点：首页卡片/列表视图、详情页（负载实时 / 负载历史 / 延迟）、后台 8 个页签。逐点遍历文本节点与 `title`/`placeholder`/`aria-label`，命中汉字即失败并报出原文。
3. **后端错误码真的翻得动** —— 5 条，见 [error-codes.md](./error-codes.md)。

**第 2 类才是漏翻的真闸门。** `Dict` 类型只保证两张表的 key 对齐，保证不了某条英文值里还留着中文 —— 那种错编译期发现不了，只有把页面真渲染出来扫一遍才抓得到。

**但第 2 类拦不住「什么都没有」**：空串同样不含汉字。所以第 3 类全是正向断言 —— 译文和不翻译的 detail（机器名、版本号）都必须真的出现在页面上。对照组实测过：抽掉一个 `{detail}` 占位符，detail 被静默吞掉，而第 2 类照样全绿。

假数据的取值是挑过的，为的是让尽量多的文案分支渲染出来：停用的密钥、过期的密钥、解不开的凭证、被 2 台节点占用的凭证、非零退出码的审计记录、prerelease 的更新、agent 过旧的节点、离线的面板宿主机。改 fixtures 时别把这些取值改「正常」了，那等于悄悄缩小覆盖面。

`upgradeHint` / `hostHint` 两条假数据**故意写成中文**，是该文件「假数据一律用英文」的唯一例外：它们是后端兜底串，翻译正常时永远不该出现，扫出来就是 bug。文件头已注明。

依赖 `playwright-core` 已写进 `package.json` 的 devDependencies，`npm i` 即可，不再需要手动临时装。它只驱动系统已装的 Chrome / Edge，不自带浏览器（约 3MB，不进生产包）。

## `utils/format.ts` 的坑

这些函数带语言状态，第 2 段处理时注意：

- `fmtUptime` 的 `天/时/分钟` 是硬编码中文
- `fmtTime` / `fmtDateTime` 硬编码 `toLocaleString('zh-CN')`
- `fmtAxisTime` 的 `时` 后缀硬编码
- `Layout.tsx` 的 `Clock` 组件里另有一处 `toLocaleTimeString('zh-CN')`

它们都是纯函数、在渲染期被调用，取语言用 `getLang()` 即可；调用它们的组件只要订阅了 `useT()` 就会在切换时重渲染。
